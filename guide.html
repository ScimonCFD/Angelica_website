User Guide

From a blank canvas to a solved network.

Everything you need to build, configure, and run a pipe-network simulation in Angelica — nodes, links, devices, settings panels, and the built-in tutorial suite.

Getting started

Launching the GUI

After installation, start the graphical interface from a terminal or command prompt. On Windows you can also use the Start-menu shortcut created by the installer.

Linux / macOS (pip install)

angelica-gui

or equivalently:

python -m angelica.gui

Windows (installer)

Double-click the Angelica shortcut in the Start Menu. The installer creates the shortcut automatically — no command is needed.

The main window opens with an empty canvas, a left-side settings panel, and a toolbar at the top. The window title shows the name of the currently open file (or Untitled for a new scene).

The drawing area

The canvas

The large central area is the canvas — a free-form drawing surface where you build your pipe network by placing nodes and drawing links between them.

  • Zoom — scroll the mouse wheel to zoom in and out. Node icons and labels scale with the zoom level.
  • Pan — click and drag the canvas background with the middle mouse button to pan the view.
  • Select & move a node — left-click to select (highlighted); drag to reposition. Press Delete or Backspace to remove the selected node and all its connected links.
  • Draw a link — right-click (or Shift+left-click) a node and drag to another node to draw a connection.
  • Edit or delete a link — right-click any link to open a context menu with Edit Components, Pressure Profile (when results are available), and Delete Connection.
  • Undo / Redo — Ctrl+Z / Ctrl+Y (or Edit → Undo / Redo) step back and forward through node placements, link additions, link deletions, and node moves.
  • Save / Open — use File → Save (Ctrl+S) and File → Open. Scene files (.gui.json) store the full scene and, when results exist, the last solve output so you can reopen and export without re-running. Tutorial files are read-only; use Save As… to save a copy elsewhere.

Network topology

Nodes

Every network is a graph of nodes connected by links. Angelica has three node types. Click the corresponding button in the top toolbar to place one, then click the desired position on the canvas.

Source

A boundary inlet node. You specify either the static pressure at this node (Pa) or the total mass flow rate entering the network here (kg/s). At least one pressure-specified source or sink is required.

Sink

A boundary outlet node. Like a source, you specify either pressure or mass flow rate. The distinction between source and sink is only visual — both can carry flow in either direction if the pressure field requires it.

Junction

An internal node where two or more pipes meet. No boundary condition is applied here — the solver enforces mass continuity (the sum of all mass flows entering equals the sum leaving). Pressure at junctions is a result, not an input.

Minimum requirement: at least one source or sink must have a specified pressure. This anchors the absolute pressure level of the solution. A network with only flow-specified boundaries is under-determined (infinite pressure solutions exist).

Links

A link is a directed connection between two nodes. To draw one, right-click (or Shift+left-click) the start node and drag to the end node.

The direction you draw the link sets the positive-flow convention displayed in results. The solver can return negative flow values if the actual flow direction is opposite to the one you drew.

Right-clicking any existing link opens a context menu with three options:

  • Edit Components — open the properties dialog to add, reorder, delete, and configure devices.
  • Pressure Profile — open the pressure-vs-distance plot for this link (only shown when results are available).
  • Delete Connection — remove the link (undoable).

Double-clicking a link opens the Pressure Profile directly when results are available, or the Edit Components dialog otherwise.

Every node must be connected to at least one link, and the network must be fully connected (no isolated sub-graphs). Angelica checks both conditions before running and shows an error listing any problems.

Network devices

Devices inside a link

Each link holds an ordered list of devices. Multiple devices in the same link are treated as being in series — the outlet of one feeds the inlet of the next. Any combination of pipes, fittings, and pumps is valid within a single link.

Pipe

A circular-cross-section conduit. Pressure drop follows the Darcy-Weisbach equation (default) or Hazen-Williams (selectable in the Pressure Drop Model panel).

ParameterDescription
length_mPipe length (m). Must be > 0.
diameter_mInternal diameter (m). Must be > 0.
height_change_mElevation of outlet minus elevation of inlet (m). Positive = uphill. Enter 0 for horizontal.
roughness_mAbsolute wall roughness (m). Typical steel: 4.5 × 10⁻⁵ m. Used only with Colebrook-White friction.
num_segmentsNumber of internal nodes along this pipe for the pressure profile plot. Does not affect the solve; use 1 for simple cases.

Fitting

A localised loss element (valve, elbow, tee, contraction, etc.) characterised by a dimensionless loss coefficient K.

ParameterDescription
k_lossMinor loss coefficient K — dimensionless. Pressure drop is ΔP = K · ½ρV².
diameter_mReference diameter for velocity calculation (m).
height_change_mElevation change across the fitting (m). Usually 0.

Pump

A centrifugal pump modelled via a head-vs-flow curve entered as a Q-Head table in the link properties dialog.

ParameterDescription
diameter_mReference diameter of the pump casing (m).
curve_points_q_headQ-Head table — one pair per line in the form Q Head (Q in m³/h, head in m). Flow must increase; head must decrease.

1 point: EPANET single-point model — power-law curve with shutoff head = 1.33 × design head.
2+ points: piecewise-linear interpolation.

Inside the Edit Components dialog you can also reorder devices with the ↑ and ↓ buttons, and delete individual devices with the Delete button. All these actions are undoable.

After a successful solve, right-click any link and choose Pressure Profile (or double-click the link directly) to see how pressure evolves along that link, with each device labelled. Pipes appear as sloped lines; fittings and pumps appear as vertical pressure steps, marked with ×.

Configuration

Settings panels

The left sidebar and the Define menu give access to four global settings that apply to the entire network.

  • Fluid Choose a working fluid. Three modes are available:

    Library — pick a preset (Water at standard conditions).

    Custom — enter density (kg/m³) and dynamic viscosity (Pa·s) directly. Use this for refined products, brines, or any liquid with known properties.

    Crude oil — enter two field parameters: API gravity (°API) and operating temperature (°C). Angelica computes density and viscosity automatically using the Beggs & Robinson (1975) dead-oil correlation before running the solver. Temperature is used only for this property calculation — the simulation itself is isothermal.

    All three modes feed the same solver. Fluid properties affect the Reynolds number in every pipe and therefore the friction-factor regime throughout the network.
  • Pressure Drop Model Selects the turbulent friction correlation for pipes. Colebrook-White (default) uses the implicit Colebrook equation with wall roughness and is valid across all turbulent Reynolds numbers. Hazen-Williams is an empirical formula for water in commercial pipes; it ignores viscosity and roughness but is widely used in water-distribution practice.
  • Numerics Controls solver behaviour. Key settings:

    Laminar / Turbulent iterations — number of outer pressure-correction iterations in each phase. The laminar phase seeds the velocity field; the turbulent phase continues until convergence or the iteration limit.

    Pressure relaxation (α) — under-relaxation factor applied to each pressure correction. Values close to 1 converge faster; values closer to 0 are more stable for stiff networks. Default: 1.0.

    Velocity loop and Friction factor — inner loop solvers (method + max iterations + tolerance) for computing V* and f at each outer iteration. Fixed-point and Newton methods are available.

    Convergence criteria — the outer loop is considered converged when both the absolute pressure correction (Pa) and the relative nodal mass imbalance |ṁin − ṁout| / (ṁin + ṁout) fall below their respective tolerances.
  • Unit System Switch between SI (m · Pa · kg/s) and other unit systems for displaying results. Input fields always accept SI values regardless of the display unit.

Simulation

Running a simulation

  1. Build the network on the canvas (nodes + links + devices).
  2. Set the fluid, pressure-drop model, and any numerics settings you want to change from their defaults.
  3. Click Run in the menu bar (or press the Run button).
  4. Angelica validates the scene first: it checks that all nodes are connected, that the graph has no isolated sub-networks, and that at least one pressure boundary exists. Any errors are shown in a dialog before the solve begins.
  5. The solver runs the laminar-phase iterations followed by the turbulent-phase iterations. A progress bar and live convergence metrics are shown during the solve.
  6. Results appear on the canvas: junction nodes show their computed pressure with a tag, and boundary nodes show the computed flow rate. The convergence history plot opens automatically during the solve and can be reopened at any time from View → Convergence Window.
  7. Click any node to see a summary popup with pressure, elevation, and connected flows. Right-click any link to open its context menu and view the Pressure Profile.
  8. Use File → Save (Ctrl+S) to persist the scene and results. Reopening the file restores the last solve output, so Export Results Report works immediately without re-running.
If the solver does not converge, try reducing the pressure relaxation factor α (e.g. to 0.5) in the Numerics panel and increasing the turbulent iteration count. Stiff networks with highly varying pipe diameters often need lower relaxation.

Tutorials

Built-in tutorial cases

Angelica ships with eleven tutorial cases in the tutorials/steady_isothermal_incompressible/ folder. Each case includes a .gui.json file you can open directly in the GUI, and a run.py script that solves the same network from Python. Open them via File → Open.

The cases are ordered by increasing complexity and cover every device and boundary-condition type supported by the current solver.

01

Pipe-only network

A branched network of six pipes with two pressure-specified sources and one pressure-specified sink. No fittings or pumps. Good starting point — demonstrates how to build a network, set boundary conditions, and interpret the pressure field at each junction.

02

Fittings — no elevation

Introduces fitting (minor loss) devices in a flat network. Shows how to add a fitting in series with a pipe inside the same link, and how to set the K-loss coefficient.

03

Fittings — with elevation

Same topology as Tutorial 02 but with non-zero height changes on pipes and fittings. Demonstrates that the hydrostatic term ρgΔz is handled automatically once height_change_m is set on each device.

04

Flow-specified inlet

A source boundary with a specified mass flow rate (instead of pressure). Requires at least one pressure-specified boundary elsewhere in the network to anchor the pressure level.

05

Flow-specified outlet

A sink boundary with a specified mass flow rate. Mirrors Tutorial 04 from the outlet side.

06

Mixed boundary conditions

A network with both flow-specified and pressure-specified sources and sinks active simultaneously. Demonstrates that multiple boundary-condition types can coexist in the same network.

07

Hanoi network benchmark

The classic Hanoi network introduced by Fujiwara & Khang [6], solved with Hazen-Williams (C = 130), matching the original problem formulation. Nodal heads and link flows are compared against reference values computed by this solver and verified for physical consistency. This is the primary validation case for the pipe solver on a large, multi-loop network.

08

EPANET pump benchmark

A pump-bearing network adapted from the official EPANET tutorial. Validates the pump curve model (quadratic head-vs-flow fit) against the EPANET reference solution.

09

Three-reservoir junction

Classic Y-junction problem: three fixed-head reservoirs connected at a common node. Junction head and pipe flows are compared against an independent analytical solution computed by bisection over the Colebrook-White equation. Agreement is within 0.001 m³/h on all flows.

10

Laminar Poiseuille benchmark

Three smooth parallel pipes carrying viscous oil (Re < 180). Volumetric flows are compared against the exact closed-form Hagen-Poiseuille solution Q = πD⁴ΔP / (128μL). Maximum relative error is below 0.001 % — confirming that the solver handles the laminar regime correctly.

11

Crude oil gathering pipeline

A branched steel pipeline carrying 32°API dead crude at 65°C. Fluid density and viscosity are computed automatically from API gravity and temperature via the Beggs & Robinson (1975) correlation — no manual property look-up required. All three pipes operate in the fully turbulent regime (Re = 19 000–31 000), solved with Colebrook-White friction.

The run.py script in each tutorial folder shows the Python API — useful if you want to drive Angelica programmatically, run parameter sweeps, or integrate it into a larger workflow without opening the GUI.
